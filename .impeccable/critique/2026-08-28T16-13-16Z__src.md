## 3. Design Specificity & Implementation Integrity Verdict

**Verdict:** **Grounded & Product-Specific (Pass with Token Consolidation Needed)**

The Workout App demonstrates exceptional domain specificity tailored directly for intense, one-handed mobile use in gym conditions:
- **Gym-Native Ergonomics:** Dark slate base (`oklch(8% 0.012 45)`) cuts high-overhead glare and prevents OLED smearing; floating sticky rest timer with haptic vibration (`navigator.vibrate`) on 0s; bottom-sheet logging formatted strictly around Set / Reps / Weight (lbs).
- **Physical Gym Literacy:** Tabular numerals (`font-variant-numeric: tabular-nums`) keep workout columns rigidly aligned; inline YouTube exercise demonstration links (`↗`) give quick form checks between sets without leaving context.
- **Offline Trust:** Live connectivity indicator (`● Offline`, `↻ Syncing…`, `N queued`) in the navigation bar gives lifters confidence in basement gyms with zero cell reception.

## 5. Priority Issues (P0–P3)

### [P1] Design System Token & Contrast Consolidation
- **What:** 68 hardcoded color literals across `HistoryView.vue`, `AuthView.vue`, `ResetPasswordView.vue`, and `App.vue`. Muted grays (`#666`, `#555`) produce ~2.8:1 contrast on dark surfaces (fails WCAG AA 4.5:1 minimum). Legacy `#e8440a` (burnt orange) lingers in Auth and App signout.
- **Why it matters:** Hardcoded grays wash out under bright overhead gym lighting. Fragmented color tokens break visual coherence across views.
- **Fix:** Unify all colors under semantic CSS variables (`--color-text-primary`, `--color-text-secondary: #a3a3a3`, `--color-primary: #a78bfa`, `--color-accent: #22c55e`). Replace legacy burnt orange with the unified palette.
- **Suggested Command:** `/impeccable colorize src` & `/impeccable typeset src`

### [P1] Ergonomics of Set Logging & Fast-Path Tap
- **What:** In the Log Workout bottom sheet, users must manually enter numbers set-by-set or deal with mobile virtual keyboards even when executing exact programmed targets.
- **Why it matters:** Shaking hands and physical fatigue between heavy sets make typing high-friction.
- **Fix:** Add a prominent "Log All as Programmed" 1-tap fast button in the bottom sheet footer, and add quick increment/decrement buttons (`-5`, `+5`, `-1`, `+1`) for weight adjustments.
- **Suggested Command:** `/impeccable adapt src/views/ProgramView.vue`

### [P2] Custom Program Card Action Clutter & Mobile Tap Safety
- **What:** `CustomView.vue` program card headers pack up to 6 buttons into a wrapped row with small 34px reorder/delete triggers.
- **Why it matters:** Distracted or sweaty thumb taps on mobile risk triggering deletion or unwanted edits.
- **Fix:** Consolidate secondary actions (`Rename`, `Export`, `Delete`) into a 3-dots overflow action menu, keeping `Edit Days` and `Activate` as the primary 48px touch targets.
- **Suggested Command:** `/impeccable layout src/views/CustomView.vue`

### [P2] Rest Timer Background Throttling & Timestamp Accuracy
- **What:** Rest timer currently relies on naive `setInterval` countdown ticks. When the mobile screen is locked or browser is backgrounded, iOS/Android throttles timer execution.
- **Why it matters:** Lifters lock their phone between sets and unlock it to find the rest timer has lagged or frozen.
- **Fix:** Store target finish timestamp (`Date.now() + targetSeconds * 1000`) and calculate remaining time against real clock on every tick and `visibilitychange` event.
- **Suggested Command:** `/impeccable harden src/views/ProgramView.vue`

### [P3] Return to Built-in Program Discoverability
- **What:** When an active custom program is selected, there is no explicit 1-tap way to revert back to the trainer's built-in "Build From Zero" track.
- **Why it matters:** Users testing custom studio routines feel locked in without an obvious restore button.
- **Fix:** Add an explicit "Reset to Built-in Program" action in Studio and an active program indicator badge in ProgramView.
- **Suggested Command:** `/impeccable clarify src/views/CustomView.vue`
